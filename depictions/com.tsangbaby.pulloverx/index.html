01 · First contact

先认识三个入口

操作集中在把手、窗口卡片和 QuickSwitch 面板。先从最少的动作开始。
快速开始手势地图核心手势快速切换设置横竖屏动态演示中心排错与常见问题
01

把手

窗口边缘的半透明小把手是 PullOver X 的总入口。轻点即可打开或关闭当前窗口。

02

窗口卡片

窗口打开后，应用内容在 PullOver 卡片里运行；键盘和方向变化会触发对应布局保护。

03

QuickSwitch

长按把手，移动到应用图标并松开，即可打开或切换窗口应用。普通窗口已打开时也能使用。

第一次使用 · 四步完成

STEP 01
打开设置系统设置 → PullOver X
STEP 02
确认 Enable保持“启用”打开；按需调左右手模式。
STEP 03
长按把手显示 QuickSwitch。若列表空，先在设置里添加收藏。
STEP 04
选图标后松手应用自动进入窗口；以后轻点把手开关窗口。

A正常的操作节奏

轻点负责开关；长按负责选应用；双击是方向和窗口状态相关的高级动作。不要把双击当成“关闭窗口”。

⌁
把手是唯一的统一入口
轻点＝打开／关闭当前窗口；长按＝调出 QuickSwitch；双击＝按当前方向和窗口状态执行高级动作。三种动作都从带应用图标的把手起手，不要把整条窗口边缘、四角或系统 Home 条当成触发区。

三个动作，先记住

•

轻点

当前窗口开 ↔ 关

关闭时会结束 PullOver 的托管显示，但不等于结束应用后台。
↗

长按

调出 QuickSwitch

普通窗口开／关均可；浮动窗口时先双击恢复。移动到图标后松手选择。
↔

双击

方向相关高级动作

横屏可进入浮动窗口；竖屏托管全屏场景可作为全屏快捷方式。
阅读提示：本说明书中的“窗口关闭”指 PullOver 面板关闭，不是杀掉应用。

02 · Gesture map

手势地图：只认把手

不是四角缩放，也不是顶部／底部快滑。先找到显示应用图标的方形把手。
①
把手轻点打开或关闭当前窗口。
②
把手长按普通窗口空闲时显示 QuickSwitch。
③
按住后移动在菜单里移动手指，停到目标应用再松开。
④
把手双击竖屏可切全屏；符合条件的横屏可缩为浮动窗口。
⑤
调整把手位置未启用“固定把手”时，可沿当前把手轨道调整位置。
⑥
内容区不是把手应用滚动、按钮与键盘仍用于操作应用，不是四角缩放入口。
方形把手与移动轨道把手中的应用图标当前应用窗口

把手位置与窗口位置要分开

普通把手沿轨道移动：调整触发位置。
浮动状态拖动把手：移动整个浮动窗口。
长按后移动到图标：选择 QuickSwitch 应用。

!
收起的把手点一次却没开窗口？
窗口关闭且侧边把手收起时，开启“把手防误触”会先唤回把手，保留至少约 2 秒可见时间；再次轻点再开窗口。这是防误触，不是失效。

窗口状态决定手势是否生效

普通开／关

长按进入 QuickSwitch；轻点切换开关。

竖屏打开

轻点关闭；双击仅在托管全屏快捷方式条件满足时动作。

浮动状态

拖把手移动；双击恢复；轻点关闭。

主屏横屏 · 有键盘

不进入浮动；双击可走窗口 UI 放大分支。

03 · Core gestures

核心手势：按状态理解

PullOver X 的双击不是单一动作；它会先判断方向、托管状态、键盘和 QuickSwitch 是否空闲。
•

轻点把手

关闭 → 打开打开 → 关闭

最基础、最稳定的开关动作。窗口关闭时如果应用尚未准备好，系统会先完成托管准备再显示窗口。
⇡

长按把手

QuickSwitch

按住约 0.3 秒显示应用菜单。普通窗口打开或关闭都可；浮动状态禁用长按，先双击恢复。
2×

竖屏双击：当前应用全屏

主屏与窗口均竖屏已展开

当前窗口应用就绪、窗口完全打开且空闲时，双击把手：先关闭 PullOver 窗口，再把该应用全屏打开。无需先开启竖屏迷你窗口。
▣

横屏双击：进入浮动窗口

主屏与窗口均横屏无键盘

窗口完全打开、应用可见、无键盘／放大／QuickSwitch 且空闲时，双击把手缩为浮动窗口；再次双击恢复原布局。

横屏浮动窗口的使用节奏

01 · ENTER
横屏打开窗口等待应用卡片稳定，键盘保持隐藏。
02 · DOUBLE TAP
把手双击卡片缩小到可用区域，并进入浮动状态。
03 · DRAG
拖动把手左右、上下移动整个浮动窗口，受屏幕安全区域限制。
04 · RESTORE
恢复再次双击把手恢复；轻点把手则关闭窗口。

横屏底部把手：向右拖收起

当窗口里的应用横屏、窗口已展开且把手位于窗口底部时，向右拖动把手可带动窗口收起；松手会根据位置与速度决定关闭或保留展开。不是所有侧边把手都支持这个动作。

＋
另一条横屏双击分支：UI 放大
主屏／外层窗口横屏且已完整展开、空闲时，才检查 UI 放大分支。主屏横屏托管竖屏 App 是本说明的演示场景；双击把手可手动切换大小。双横屏且无键盘等条件满足时，双击优先进入浮动；实际放大受可用空间限制。
!
先看窗口状态，再判断动作。浮动、全屏和 UI 放大是不同分支。转场中、应用未就绪或空间不足时，动作可能被跳过；不要连续乱点叠加输入。

QuickSwitch 选中的应用窗口内打开

最稳的三步

1从普通窗口的把手按住不放。

2移到目标图标，看到选中反馈。

3在图标上松手，应用自动在窗口里打开或切换，无需再点把手。

QuickSwitch 的设置项

A显示来源

  • Style · 样式
    Recent Apps：最近应用；Favorite Apps：收藏应用。
  • Select Favorite Apps
    进入列表点选并调整收藏应用。
  • Recent Apps Count
    仅在“最近应用”样式下显示；默认 5，可设 1–99。

B每页容量

  • 竖屏每页应用数
    默认 12，可设 1–99；不是总收藏数，实际受屏幕空间限制。
  • 横屏每列应用数
    默认 10，可设 1–10；主屏横屏采用双列布局。
  • Hide QuickSwitch Labels
    隐藏拖拽全屏目标的提示文字，不影响图标选择。

翻页

应用超过当前页容量时，继续按住并停在上一页／下一页箭头上约 0.2 秒翻页，然后移到目标图标。

收藏排序

在“选择收藏的应用”中点选应用，拖动“已选择的应用”右侧排序柄改变顺序；搜索时不支持重排。

拖出图标 → 全屏

选中应用后，继续拖到中间的打开目标区并松手：转为该应用的原生全屏打开，不是在窗口内选择。

i
当前前台应用不在菜单里？QuickSwitch 会暂时过滤当前主屏前台应用，并不删除已保存的收藏。
屏幕录制：收藏列表的系统应用区可添加；选择它会切换系统录屏，而不是打开一个录屏窗口。

外部应用打开：什么会进入窗口？

✓两个独立开关

启用外部 URL 窗口化：默认关闭。开启后，普通自定义链接和符合条件的 Universal Links 可以在窗口里打开。

启用通知横幅窗口化：默认开启，独立控制通知点击的窗口路由。

!外部链接排除项

“在选定的应用中禁用”与“排除的网页链接域名”用于让外部链接保留原生打开。域名示例：
example.com, accounts.example.com
系统及敏感链接始终保持原生，不强制窗口化。

Appendix · Troubleshooting

排错与常见问题

最后一页集中整理常见问题和日常配置。

把手完全看不到？

先确认 Enable；再检查 Hide in Landscape、截图隐藏、左手／双侧把手和收起比例。若开启自动收起，轻点收起位置把它唤回。

长按没有 QuickSwitch？

从把手按住约 0.3 秒，不要快速划走；等开关动画结束。浮动窗口先双击恢复；列表为空时检查样式及收藏。

双击没有反应？

先分清主屏与窗口的方向；竖屏全屏要求应用就绪；横屏浮动要求无键盘及放大。主屏横屏的 UI 放大还需要窗口空闲与足够空间。

窗口关闭是不是结束应用？

不是。PullOver 关闭的是窗口托管显示；应用是否留在后台由 iOS 系统规则决定。需要退出应用请使用系统自己的方式。

外部链接仍然原生打开？

检查 External URL Routing 是否启用，以及应用／域名是否被排除。系统和敏感链接本来就保持原生；并非所有 Universal Link 都具备窗口化资格。

设置改了但界面没变？

回到偏好页确认值已经保存；如果出现“请注销”，按页面提示执行 Respring。不要把一次布局过渡延迟当作配置丢失。
